# Non-Keyblock Key Update

Use these methods when the terminal and host exchange encrypted keys and key check values directly, without a TR-31 key block. The examples below use placeholders for keys and KSNs. Replace them with values generated by your HSM or key-management system, and never use sample or factory keys in production.

<Tabs items={['DUKPT', 'MKSK']}>
  <Tab>
  ## DUKPT

  DUKPT IPEKs can be updated under the terminal's configured TMK, or with a temporary transport key exchanged using RSA.

  ### Update IPEK by TMK

  Encrypt each IPEK with the same TMK configured in the terminal. Calculate its KCV by encrypting a zero block with the clear IPEK; the examples below pass the first six hexadecimal characters as the KCV.

  ```java
  String encryptedTrackIpek = TDES.tdesECBEncrypt(tmk, trackIpek);
  String trackIpekKcv = TDES.tdesECBEncrypt(trackIpek, "0000000000000000").substring(0, 6);

  String encryptedEmvIpek = TDES.tdesECBEncrypt(tmk, emvIpek);
  String emvIpekKcv = TDES.tdesECBEncrypt(emvIpek, "0000000000000000").substring(0, 6);

  String encryptedPinIpek = TDES.tdesECBEncrypt(tmk, pinIpek);
  String pinIpekKcv = TDES.tdesECBEncrypt(pinIpek, "0000000000000000").substring(0, 6);

  pos.doUpdateIPEKOperation(
      keyIndex,
      trackKsn, encryptedTrackIpek, trackIpekKcv,
      emvKsn, encryptedEmvIpek, emvIpekKcv,
      pinKsn, encryptedPinIpek, pinIpekKcv
  );
  // Callback: onReturnUpdateIPEKResult(boolean isSuccess)
  ```

  ### Update IPEK by RSA

  Call `generateTransportKey` to start the RSA transport-key exchange. In `onRequestGenerateTransportKey`, decrypt the returned `transportKey` with the corresponding RSA private key. Use that transport key to encrypt each IPEK, calculate each IPEK's KCV, and pass the encrypted IPEKs and KSNs to `updateIPEKByTransportKey`.

  ```java
  pos.generateTransportKey(timeout);

  // In onRequestGenerateTransportKey(Hashtable result):
  // 1. Decrypt result.get("transportKey") with the matching RSA private key.
  // 2. Encrypt the IPEKs with that transport key and calculate their KCVs.
  pos.updateIPEKByTransportKey(
      keyIndex,
      trackKsn, encryptedTrackIpek, trackIpekKcv,
      emvKsn, encryptedEmvIpek, emvIpekKcv,
      pinKsn, encryptedPinIpek, pinIpekKcv
  );
  // Callback: onReturnUpdateIPEKResult(boolean isSuccess)
  ```

  ## MKSK

  MKSK (Master/Session) working keys and master keys can be updated under the terminal's configured TMK.

  ### Update session keys by TMK

  Encrypt the PIN, track, and MAC session keys with the current TMK. Calculate each key's KCV by encrypting a zero block with that clear key.

  ```java
  String encryptedPinKey = TDES.tdesECBEncrypt(tmk, pinKey);
  String pinKeyKcv = TDES.tdesECBEncrypt(pinKey, "0000000000000000").substring(0, 6);

  String encryptedTrackKey = TDES.tdesECBEncrypt(tmk, trackKey);
  String trackKeyKcv = TDES.tdesECBEncrypt(trackKey, "0000000000000000").substring(0, 6);

  String encryptedMacKey = TDES.tdesECBEncrypt(tmk, macKey);
  String macKeyKcv = TDES.tdesECBEncrypt(macKey, "0000000000000000").substring(0, 6);

  pos.udpateWorkKey(
      encryptedPinKey, pinKeyKcv,
      encryptedTrackKey, trackKeyKcv,
      encryptedMacKey, macKeyKcv,
      keyIndex
  );
  // Callback: onRequestUpdateWorkKeyResult(UpdateInformationResult result)
  ```

  ### Update master key by TMK

  Encrypt the new master key with the current TMK, then calculate the new key's KCV. On first injection, use the configured initial TMK; for later rotations, use the currently installed TMK.

  ![TMK update flow](/images/non-keyblock-tmk-update.png)

  ```java
  String encryptedNewMasterKey = TDES.tdesECBEncrypt(tmk, newMasterKey);
  String newMasterKeyKcv =
      TDES.tdesECBEncrypt(newMasterKey, "0000000000000000").substring(0, 6);

  pos.setMasterKey(encryptedNewMasterKey, newMasterKeyKcv, keyIndex);
  // Callback: onReturnSetMasterKeyResult(boolean isSuccess, Hashtable<String, String> result)
  ```
